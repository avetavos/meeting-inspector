# แก้บทได้ตามใจ — ใส่ศัพท์ที่ทีมคุณใช้จริงจะวัดได้ตรงกว่า

TERMS: deploy, backend, frontend, staging, production, rollback, pull request, code review, merge, migration, endpoint, cache, Redis, PostgreSQL, index, query, timeout, retry, sprint, backlog, refactor, unit test, pipeline, Docker, log, monitoring, alert

สวัสดีครับทุกคน วันนี้เรามาทำ sprint planning กันนะครับ ผมขอเริ่มจากสรุปของ sprint ที่แล้วก่อน

งานที่ค้างอยู่ใน backlog ตอนนี้เหลือสามใบ ใบแรกคือเรื่อง migration ของตาราง user ที่เรายังไม่ได้ทำ เพราะรอ code review จากทีม backend อยู่

ผมเปิด pull request ไว้ตั้งแต่วันอังคารแล้ว แต่ยังไม่มีใคร merge ให้ ถ้าใครว่างช่วยเข้าไปดูให้หน่อยนะครับ

เรื่องที่สองคือ endpoint ตัวใหม่ที่ frontend รออยู่ ผมทำเสร็จแล้วแต่ยัง deploy ขึ้น staging ไม่ได้ เพราะ pipeline มันพังตอน build Docker image

ผมดู log แล้วเจอว่ามันเป็น timeout ตอนดึง dependency ลองใส่ retry เพิ่มอีกสามครั้งน่าจะพอ

เรื่องที่สามหนักกว่าเพื่อน คือ query ที่หน้า dashboard มันช้ามาก บน production ใช้เวลาเกินสิบวินาที

ผมลองดูแล้วคิดว่าปัญหาอยู่ที่เราไม่ได้ทำ index ให้ column ที่ใช้ join ใน PostgreSQL ถ้าเติม index ตัวเดียวน่าจะเร็วขึ้นเยอะ

อีกทางคือเอา Redis มาทำ cache ให้ผลลัพธ์ตรงนี้ แต่ผมว่าอย่าเพิ่งดีกว่า แก้ที่ต้นเหตุก่อน อย่าเพิ่งเพิ่มของใหม่เข้าระบบ

สำหรับ sprint นี้ผมอยากให้เราเน้นสามเรื่อง หนึ่งคือเคลียร์ของค้างให้หมด สองคือทำ refactor ส่วน authentication ที่มันรกมานาน สามคือเพิ่ม unit test ให้ครอบคลุมกว่านี้

เรื่อง monitoring ผมตั้ง alert ไว้แล้วนะครับ ถ้า error rate เกินหนึ่งเปอร์เซ็นต์มันจะเด้งเข้า Slack ทันที

ถ้า deploy แล้วมีปัญหาให้ rollback ก่อนเลย อย่าพยายามแก้สดบน production เดี๋ยวจะยิ่งพัง

โอเคครับ ใครมีอะไรจะเสริมไหม ถ้าไม่มีผมขอปิดประชุมตรงนี้ ขอบคุณทุกคนมากครับ
