# จำลองประชุม 4 คน — ตัดสินใจเรื่องสถาปัตยกรรม
# CAST: ชาย+หญิง
# TERMS: ศัพท์ที่ต้องออกมาเป็นภาษาอังกฤษ

TERMS: architecture, service, monolith, microservice, database, cache, Redis, queue, latency, throughput, scale, deploy, rollback, migration, API gateway, load, cost

ต้น: วันนี้เรามาตัดสินใจกันเรื่องว่าจะแยก service ออกจาก monolith ไหมนะครับ
ฝ้าย: ฝ้ายว่าถ้าแยกตอนนี้มันเร็วไปนะคะ ทีมเรามีสี่คน ดูแล microservice หลายตัวไม่ไหวแน่
บอย: ผมเห็นต่างนิดนึงครับ ตอนนี้ตัว report มัน scale แยกไม่ได้เลย เวลามีคนโหลดรายงานหนักๆ ทั้งระบบช้าตาม
มิ้น: ข้อมูลฝั่ง monitoring ก็เห็นแบบนั้นค่ะ latency ของ API ตัวอื่นขึ้นตามทุกครั้งที่มีคนดึงรายงาน
ต้น: แล้วถ้าเราแค่ใส่ queue กับ cache ก่อน ไม่ต้องแยก service เลย จะพอไหม
บอย: ช่วยได้ระดับหนึ่งครับ แต่ไม่แก้ที่ต้นเหตุ เพราะมันแย่ง database ตัวเดียวกันอยู่ดี
ฝ้าย: ถ้าจะแยกจริง ต้องคิดเรื่อง migration ของข้อมูลด้วยนะคะ อันนั้นงานใหญ่กว่าตัว service อีก
มิ้น: แล้วเรื่อง cost ล่ะคะ แยกออกไปแปลว่าต้องมีเครื่องเพิ่ม มี API gateway เพิ่ม
ต้น: ผมว่าเราทำเป็นสองขั้นดีกว่า ขั้นแรกใส่ Redis กับ queue ก่อน วัดผลสองสัปดาห์
บอย: ถ้าตัวเลขยังไม่ดีค่อยแยก service จริงใช่ไหมครับ
ต้น: ใช่ครับ แบบนี้ถ้าพลาดก็ rollback ง่าย ไม่ต้องรื้อทั้งระบบ
ฝ้าย: ฝ้ายโอเคกับแผนนี้ค่ะ
มิ้น: มิ้นด้วยค่ะ เดี๋ยวจะเตรียม dashboard วัด latency กับ throughput ไว้ให้ก่อน
ต้น: ดีครับ สรุปว่าขั้นแรกทำสองอย่างนี้ แล้วมาคุยกันใหม่อีกสองสัปดาห์ครับ
